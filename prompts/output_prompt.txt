Flexi Manager Continuous Reference-Power Fail-Closed Report

Root cause:
flexi_manager.py still allowed continuous/modulated activation to compute an absolute target from nominal_power_kw when no bid-record reference power was available. For strategy_10/recent_profile, the accepted curtailment is relative to the asset-level bid reference power, not the nominal asset capacity, so nominal_power_kw - allocated_curtailment_kw can produce a target above actual/reference consumption and deliver no real curtailment.

Behavior before:
- Continuous assets without reference_power_kw fell back to nominal_power_kw.
- Example: nominal_power_kw=11.00 and allocated_curtailment_kw=2.99 produced target_power_kw=8.01.
- Allocation logs also displayed a nominal fallback reference.
- Skipped/fail-closed behavior was not enforced for missing continuous reference power.

Behavior after:
- Continuous/modulated assets require a valid positive finite reference_power_kw.
- Preferred bid-record field is reference_power_kw, with reference_power_source preserved when present.
- Other historical reference fields are still accepted additively when present, but non-positive, NaN, and infinite values are rejected.
- If the reference is missing or invalid, the asset result is status=skipped, no command payload is queued, actual_curtailment_kw is 0, and nominal fallback is explicitly disabled.
- If all allocated assets are skipped or otherwise non-deliverable, the activation summary reports status=activation_failed and total_flexibility_deliverable_kw=0.
- nominal_power_kw is still used only as an upper safety cap: target_power_kw = min(max(min_power_kw, reference_power_kw - allocated_curtailment_kw), nominal_power_kw).

- Continuous invalid reference values (None, NaN, 0, negative) skip activation.

- Lower bound clamps target to min_power_kw when reference - curtailment is below minimum.
- Upper cap clamps target to nominal_power_kw only as a safety cap.
